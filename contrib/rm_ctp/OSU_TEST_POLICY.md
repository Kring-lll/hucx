# 标准OSU验收约定

生效日期：2026-10-28。用户确认后续正式功能与性能验收使用标准OSU，不再新增自编demo作为验收用例。

## 固定原则

- 沿用已安装的OSU 7.5.2原版二进制。记录版本、二进制哈希、MPI与UCX来源、配置、消息尺寸、拓扑、PPN、绑定、校验、退出码和重复样本；升级版本另列基线。
- 自动化脚本负责启动、配置、校验结果解析、库加载取证、资源采集和汇总，不改OSU通信算法或计时逻辑。
- 独立数据校验、无URMA观察器计时、独立资源观察分轮。是否有校验选项及其语义以当前版本源码和帮助为准，不假设所有用例参数相同。
- 每次小改动选少量受影响用例快速回归；阶段交付扩展消息尺寸、并发规模与重复次数。用例数量不是目标，不承诺全套OSU全部通过。
- 原始失败、波动和回退均保留。没有同规模RC基线时填XX（未测），不宣称相对收益。
- 已有自编专项保留为历史证据，不改标OSU、不删除共享历史；新的正式结果以标准OSU为主。
- OSU无法直接证明内部引用、真实丢包恢复或原生操作选择。未覆盖项明确标注；确需额外专项时先说明原因，不默认另写demo补洞。

## 按需求选择用例

| 阶段 | 主要标准用例 | 验证目的与边界 |
|---|---|---|
| A及后续快速回归 | osu_latency、osu_multi_lat、osu_alltoall | 小包时延、并发和多对端关系；已有8B结果作为基线 |
| B1～B3 | osu_latency、osu_bw、osu_bibw，随后osu_multi_lat、osu_mbw_mr及选定集合用例 | 从源码确定边界，再覆盖边界前后、非整片和多片；不把默认尺寸曲线自动当作所有边界覆盖 |
| B集合场景 | osu_alltoall、osu_allgather、osu_allreduce、osu_bcast等按目标选择 | 不同通信关系及大小消息，不要求每个集合变体都纳入当前任务 |
| 初始化成本补充 | osu_init、osu_hello（核对构建与支持） | 启动/退出指标不代替首次业务通信；不能从稳定时延推出建链耗时 |
| B4原生操作 | 对应osu_put_*、osu_get_*，能力满足后选用 | MPI单边测试通过不等于底层必走原生RM READ/WRITE，需路径证据 |
| C恢复开发后 | 对应已支持路径的标准OSU数据验证 | 故障来源、注入方法和恢复判据另行明确；普通OSU成功不能证明重传完成 |

正式测试矩阵取“相关用例×消息尺寸×PPN×重复次数”，按实现范围递增，不进行无关GPU、原子、多线程或其他编程模型测试来扩大项目范围。

## 资源与统计口径

时延、带宽、消息率、集合耗时分别列出，不混成一个指标。Jetty为目标模式每进程同时存活峰值及全rank范围，辅助UM另计。RSS为进程驻留内存，包含MPI/UCX/缓冲和可能重复统计的共享页，不能称Jetty专属或设备内存。本项目既有表采用各rank Finalize前RSS之和的五轮中位数，非同步瞬时总量。

现阶段正式表限定标准OSU固定8B：RM/RC对照至PPN20，RM两用例扩展至PPN160。PPN192超时未解决并暂停，不列为通过，不把160当协议上限。
