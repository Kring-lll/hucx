# 无DATA PSN的RM实验副本

本分支 `rm-um-send-nopsn-dev` 从工具提交56c8913f5c69bf99f483f3a18c5152fa18dec029分出，产品基线仍是已测a4d07599bd5b66b84c5de8257e5f7fe15e3a6f63的src树。
完整RM的分支、目录、安装和结果保持不变。本副本用于正常路径成本对照，不是新的可靠性方案，不继承完整RM的节点验收。

## 精简了什么

| 项目 | 完整RM | 本副本 |
|---|---|---|
| DATA前缀 | packet_type32 + psn16 + ack_psn16，8B | packet_type32 + ack_psn16，6B |
| DATA发送 | 把PSN写到线上头 | 只把本地窗口键保存为skb.local_psn，不发送 |
| DATA接收 | 读PSN，判失序/重复，推进frag_list | 不读DATA PSN、不逐包比较；按到达次序推进本地连续计数 |
| ACK和建链控制头 | 8B，含PSN与ACK序号 | 保留8B及原控制处理 |
| 窗口、ACK请求时机、拥塞和释放 | UM框架 | 保留，改用本地skb键回收DATA |
| DATA重发 | 按序号重发 | 一旦实际选中DATA重发就使样本失败，禁止重复误交付 |
| 建链重发 | UM原路径 | 保留 |
| AM_BCOPY能力 | 4088B | 保持4088B，避免UCP分片阈值同时改变 |
| AM_SHORT能力与选择阈值 | 原能力 | 保持原能力，即使较短头还可容纳更多字节也不扩大 |
| 单次SEND | 不超4096B | 不超4096B；满AM_BCOPY通常4094B |
| skb大小 | 64B对齐 | 仍64B；本地键使用原有对齐空间 |

去掉了线上2B DATA PSN和相应接收判定，但保留了ACK序号及内部窗口计数。因此不能把结果称作“完全无PSN”或“整个软件可靠性开销”。差值包含头长、打包/解析/判定与布局等共同变化，不是某一条赋值语句的纯耗时。
不把发送窗口按本地CQE直接释放，不整套删除重传代码，不另起新建链状态机。

## 正确性边界与互通隔离

实验假设DATA按序且无重复、无丢失交付。没有线上DATA序号就无法可靠识别DATA丢失/重复/乱序，也不能保证与完整RM相同的端到端故障语义。
ACK字段不删除：它负责推进发送窗口和安全释放缓冲；删掉ACK会变成另一种流控/生命周期方案，超出本轮。
若重传计时器实际选择重发DATA，输出明确Fatal并停止该样本；不静默重发然后把重复包当新数据。这个失败也能检验“正常测量不会触发重发”的前提。
ACK控制、CREQ/CREP、原有超时/退避/重传例程和软件PUT内部路径保留；READ/WRITE/AM_ZCOPY仍不上报能力。

为避免一端完整头、一端短头误解码，本副本在原8B iface/EP地址的trans_mode字段中带一个位30格式标记；这是仅在地址交换中使用的标识，不是新的URMA传输模式。
导入前必须验证该标记，真正传给URMA的模式仍是URMA_TM_RM，TP仍CTP。legacy地址会在导入前拒绝；完整RM看到不支持的地址模式也无法正常建链。只支持两端同一副本构建。
不改变地址长度，不在每个DATA中增加新标记，也不新增协商协议。

接收内存池保持原8B布局和对齐，初始化完成后将RM接收起始偏移后移2B；6B头后面的AM payload、用户headroom与release_desc仍在原对齐位置，不增加整包memmove。异步pending接收和延迟释放同步采用实际头长。
