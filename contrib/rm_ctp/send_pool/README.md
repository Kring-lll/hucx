## 产品变化

仅修改rm_urma_iface.c和rm_urma_reliable.c，14行新增、7行替换。
复用现有tx.pending_mp软件操作池；只在reliable_v3模式把元素大小上界扩至能容纳重放记录。
不新增池、配置、产品文件或结构体字段，不预分配全部peer窗口。
池原有128元素/块、按需增长和iface关闭时清理的方式不变。
池的空闲块可能保留到iface关闭，RSS效果必须实测，不能预先保证减少。
legacy_ep/iface_v2的池元素大小保持原样。

DATA及ACK元数据取自该池，取出后完整清零，保证不会带入旧ACK、CQE、重试或隔离状态。
六处原free(entry)分别改为归还池；TX数据描述符仍取自原tx.mp。
正常回收仍要求本地完成/远端确认满足原条件；隔离记录仍等Jetty停止、控制EP操作清理后才回收。
不改变接收窗口或共用Jetty调度，不设置会影响既有flush/控制请求的新池容量限制。

## 节点验证

新提交源码在新的r1_shared目录隔离构建，不覆盖a2b、诊断库或旧结果。
复用既有验收工具：28项legacy/iface_v2/RC正常回归、11项OSU边界及至1MiB消息、
两项严格大小交替、一次原版OSU软件丢DATA/ACK/重复注入、六项有界退出。
软件注入不代表硬件丢包。

正式性能对照：旧可靠=已开启inline的a2b产品；新可靠=本池复用候选；RC=新候选库RC。
同一批multi_lat PPN1、alltoall PPN4的8B原版OSU，三模式各1校验、5计时、1独立资源轮，
计时顺序轮换、保留全部原值。共56项MPI+28项正常回归、6项定向UCT退出。
正式计时没有profiling、WR/故障/资源观察器；Init/Finalize身份探针保持一致。
RSS为Finalize前各rank求和，采样不同步，不是设备内存；Jetty在独立资源轮记录。

本地用截取的真实生产函数做CPU所有权模型，覆盖脏记录复用、元数据/描述符池失败、
ACK/CQE两种顺序、资源不足回滚、终止错误隔离、共享控制记录和关闭清理。
ASAN/UBSAN开关断言两轮；所有模型池槽及guard检查，但容器不支持LeakSanitizer，未作LSAN结论。
模型不是URMA ABI或设备测试。ARM整库构建、实际节点功能和性能收益仍待验收。
READ/WRITE、默认模式改变、完整C/D及硬件故障不在本次范围。
